# MsgOutEditor 需求文档

> 聊天输出框(消息列表显示控件)——功能需求与视觉规格。
> 实现基于 hmskin 框架,本文档不规定代码实现细节。

## 1. 概述

MsgOutEditor 是一个聊天输出框控件,呈现垂直排列的聊天消息列表,支持富内容显示、滚动浏览、文字选取复制。定位为只读显示控件(不含编辑/光标)。

与聊天输入框(hmeditor 项目)配合使用:输入框负责编辑发送,输出框负责呈现历史。

## 2. 消息模型

### 2.1 消息类型

| 类型 | 呈现位置 | 说明 |
|---|---|---|
| 对方消息(PEER) | 头像+气泡靠左 | |
| 自己消息(SELF) | 气泡+头像靠右 | |
| 系统通知(SYSTEM) | 居中灰色小字 | 时间分隔条、"xxx 撤回了一条消息"等 |

### 2.2 消息元数据

| 字段 | 用途 |
|---|---|
| 发送者标识 | 决定消息左右位置 |
| 时间戳 | 决定是否显示时间分隔条 |

### 2.3 内容类型(可扩展)

消息内容由多个内容项组成,内容项类型必须支持后续扩展,预留抽象接口。

| 内容项 | 排列方式 | 说明 |
|---|---|---|
| 文字(TEXT) | 行内 | 可指定字体、颜色、大小 |
| 表情(EMOJI) | 行内,与文字混排 | 小尺寸图片,跟文字同一流 |
| 静态图片(IMAGE) | **块级,独占一行** | 放在所有行内内容下方 |
| 动图GIF(GIF) | 块级,独占一行 | 播放动画 |
| (扩展) | 由业务定义 | 通过抽象接口接入 |

**关键规则**: 文字和表情在同一流内从左到右排列、超宽换行;图片/动图不参与行内混排,各自独占一行,依序放在行内内容区域下方。

### 2.4 内容项通用约束

- 所有内容项支持"可扩展抽象接口",新业务类型无需修改控件核心代码即可接入
- 图片类内容项需同时支持**文件路径**和**位图句柄**两种传入方式

## 3. 视觉规格

参照微信 PC 客户端:

| 元素 | 规格 |
|---|---|
| 气泡最大宽度 | 可用宽度 × 80% |
| 气泡底色(对方) | 白色或浅灰 |
| 气泡底色(自己) | 绿色(#95EC69) |
| 气泡圆角 | 约 6-8px |
| 头像 | 约 40px,对方在左/自己在右(v1 可用色块占位) |
| 昵称 | 显示在气泡上方(v1 可不实现) |
| 时间分隔条 | 居中灰色小字,间隔约 5 分钟显示一次 |
| 消息间距 | 约 8-12px |

## 4. 布局

1. **气泡宽度自适应**: 消息内容短则气泡窄,长则封顶 80% 可用宽度后换行
2. **行内混排换行**: 文字+表情在同一流内,从左到右排列,放不下换行;文字在**词边界**断行(非任意字符处)
3. **图片尺寸钳位**: 超过限定尺寸(参考 240×240)时等比缩小显示,不放大
4. **消息独占垂直块**: 消息之间不重叠、不嵌套,每条消息是一个完整的垂直单元

## 5. 滚动

| 行为 | 说明 |
|---|---|
| 垂直滚动 | 浏览历史消息 |
| 自动贴底 | 新消息到达且用户当前在底部时,自动滚到新消息 |
| 不打扰 | 用户向上翻看历史时,新消息到来**不**自动滚动 |
| 滚动条显示/隐藏 | 默认显示;输出框**无焦点且鼠标移出**时自动隐藏 |

## 6. 选取与复制

### 6.1 双模式选取

| 模式 | 粒度 | 用途 |
|---|---|---|
| 文字选取 | 字符级,可**跨消息**(同时选多条消息各自的部分文字) | 复制文字 |
| 整消息选中 | 消息级,选中完整消息单元 | 将来多消息转发 |

### 6.2 功能清单

| 功能 | 优先级 |
|---|---|
| 消息内文字选取 | v1 |
| 跨消息文字选取 | v1 |
| 双模式切换 | v1 |
| Ctrl+A 全选 | v1 |
| 复制选区文字(纯文本) | v1 |
| 图片另存/复制 | 后续 |
| 右键菜单(复制/删除/撤回/转发) | 后续 |

## 7. 性能

| 场景 | 策略 |
|---|---|
| 消息少(内容 < 3 屏高) | 全量渲染 |
| 消息多(内容 ≥ 3 屏高) | **增量渲染**: 初始只渲染可视区附近,滚动到边界时追加 10/20 条 |
| 高频追加(连续收发) | 新消息**增量追加**显示,不整屏重绘 |
| 大量图片 | **按需加载/缓存**,不一次性全部解码 |

## 8. 与聊天输入框(hmeditor)的协作

### 8.1 发送流

```
用户在输入框打字 → Enter 发送
  → 输入框内容传递到输出框,组装成一条消息
  → 输出框追加显示 + 自动滚底
  → 输入框清空
```

### 8.2 数据传递

- 考虑扩展 hmeditor 的 JSON 交换格式(`hmeditor_data_exchange_output_format`)作为输入到输出的内容载体
- 需要扩展的语义: 区分行内内容(表情)与块级内容(图片)
- 图片支持文件路径和位图句柄两种传递方式

### 8.3 对外 API

- 输出框提供**抽象接口**,支持可扩展的消息复合/复杂类型
- 新业务类型通过接口接入,无需修改输出框核心代码
- 具体接口签名由实现方(hmskin)结合框架设计决定

## 9. 与 hmskin 框架的集成

| hmskin 组件 | 集成方式 |
|---|---|
| 滚动 | v1b 把纵向滚动状态机抽成共享纯类 `hm_scroll_core`,msgout **自持滚动**(直接驱动 scrollbar,无内容 keelobj);`hm_wmp_scrollview` 保留给静态子树场景 |
| 布局系统(layout_obj + decoder) | 直接使用 |
| 消息路由(msg_sink) | 按 hmskin 其他控件的消息模式接入 |
| 皮肤/主题 | v1 不做,预留扩展能力(气泡/头像色走 MsgOutCfg) |

## 10. 明确不做的事(当前版本)

- 块内光标/编辑(输出框是只读显示)
- 消息撤回/删除/转发的实际业务逻辑(仅预留消息级选取能力)
- 多人聊天(群聊)的复杂头像/昵称布局
- 主题/皮肤定制(v1 写死微信风格,后续开放)
